# GitHub

## Papel do GitHub

O GitHub deve funcionar como prova pública de evolução técnica.

Não basta ter repositórios.

Os projetos precisam ter:

* README claro;
* descrição do problema;
* stack usada;
* como rodar;
* prints ou exemplos;
* próximos passos;
* status do projeto;
* aprendizados.

## Mensagem estratégica

> GitHub precisa contar a mesma história que o LinkedIn.

## Conteúdos possíveis

* Como estou melhorando meus READMEs.
* Por que portfólio técnico precisa de contexto.
* O que um recrutador deveria entender ao abrir meu GitHub.
* Projeto sem explicação perde força.
* Como estou conectando LinkedIn, GitHub e portfólio.

# Cuidados editoriais

Evitar frases como:

* “sou especialista em tudo isso”;
* “domino completamente”;
* “sou referência em IA”;
* “criei um sistema revolucionário”;
* “agentes autônomos que fazem tudo sozinhos”;
* “automatizei 100% da minha carreira”.

Preferir frases como:

* “estou estudando e aplicando”;
* “estou construindo”;
* “estou aprendendo na prática”;
* “esse projeto me ajuda a entender”;
* “minha meta é transformar isso em produto real”;
* “ainda está em evolução, mas já me ensinou muito”.
